# 機能要件とユースケース

## 1. 機能要件

### チャット & メッセージ機能 (Phase 1)

- 端末間のリアルタイムメッセージ送受信（Firestore リスナー連携）
- E2EE によるメッセージ暗号化（1:1 は $SK_{direct}$、かいぎは $SK_{group}$）
- 過去メッセージの動的ページネーション取得（初期 30 件、スクロールによる追加オンデマンド取得）
- **既読管理**: 水位線カーソル（`ReadReceipt`）による各参加者の既読位置・日時のリアルタイム同期
- **メッセージリアクション**: 7 種類の絵文字リアクション、タップ集計および長押しによるリアクションユーザー詳細表示

### アカウント & プロフィール管理 (Phase 1)

- 匿名アカウントの作成（ゲスト利用開始）
- 永続アカウントの登録・管理（Firebase Auth）
- 端末移行を実現するための「ふっかつのじゅもん（Mnemonic Phrase）」発行・保管・復元
- **プロフィール & アバター管理**:
  - 表示名の $MK_T$ による AES-256-GCM 暗号化保存
  - Cloudflare R2 を用いた暗号化アバター画像のアップロード・CDN 配信・キャッシュ復号

### テナント管理 (Phase 1)

- テナント（組織）ごとの設定を利用開始前に構成
- テナント作成後にテナント情報を含むQRコードを生成・出力（ダウンロード / 印刷）
- 利用者はその QR コードをスキャンしてテナント参加（利用開始）
- サービスのデフォルトテナント設定（指定がなければ自動利用）
- QR スキャンの代替としてテナント設定を手動で入力できる `JSON` 入力UI を提供（テンプレート付き）
- テナントごとにマスターキー（$MK_T$）を保持し、個々のユーザー端末のローカル鍵と組み合わせて組織内データを暗号化
- マスターキーのみでメッセージ内容を復号できない設計（ゼロ知識暗号化）
- テナント内のメタデータ監査を可能にするが、本文は閲覧不可（※専用サーバーAPIは現行未実装であり、クライアント直接アクセスによる Firestore Security Rules で保護）

### かいぎ管理（グループチャット / Phase 1）
※ 本アプリではグループチャットを「かいぎ」と呼びます（英語表記は `Group chat`、ID体系: `gm_...`）。

- テナント内におけるかいぎの作成・編集・かいぎ削除・メンバー管理機能
- ユーザーは同一テナント内の複数のかいぎに所属可能
- **メンバー属性とロール管理**:
  - 各メンバーは属性としてロール（`owner`: オーナー、`admin`: 管理者、`member`: 一般メンバー）を保持
  - **グループオーナー**: 初期作成者が就任（1かいぎ1名）。自らかいぎを退出することは不可。かいぎ削除、管理者任命、**他メンバーを退出させること**（左スワイプ操作）、**かいぎ名変更**が可能
  - **グループ管理者**: オーナーまたは管理者が任命可能（複数名可）。**自らオーナーに昇格（立候補ダッシュ型）可能**（前任オーナーは管理者にスライド）。かいぎ削除、管理者任命、**他メンバーを退出させること**（左スワイプ操作）、**かいぎ名変更**が可能
  - **一般メンバー**: チャット送受信、メンバー招待（追加）、自らかいぎを退出することが可能（※他者を退出させることは不可）
- **かいぎ削除（重要操作）**:
  - オーナーまたは管理者が実行可能
  - 誤操作防止のため **削除確認ダイアログ（重要警告付き1回表示）** を経て実行
  - 削除実行時はメンバー一覧をクリア（`members: []`）し、全メンバーのチャット一覧から非表示化しつつ監査メタデータを保持
- **デフォルトかいぎ機能**:
  - テナントごとに全体連絡用などのデフォルトかいぎを設定可能
  - 新規ユーザーがテナントに参加した際、デフォルトかいぎに自動的にアサインされる仕組みを提供
- **グループ鍵ローテーション（Forward / Backward Secrecy）**:
  - メンバー追加・除外の変更時点以降を対象として新規鍵バージョン（`KeyBucket`）を発行

### ソーシャル機能 (Phase 1)

- **友達登録・管理**:
  - 対面 QR コードスキャンによる友達追加
  - テキスト共有（URL / トークン連携）
  - **30秒更新3桁合言葉（TOTP）**: QR コード読取困難時の 3 桁数字照合による安全な友達追加

### 通知 (Phase 1)

- アプリ内トースト通知（フォアグラウンド受信時）
- Firebase Cloud Messaging (FCM) / APNs を利用したプッシュ通知
- **外部システム連携REST APIによる通知送信**:
  - 外部システムからの REST API コールにより、指定した1つのテナント内の指定した複数かいぎ（グループチャット）に対して一括で通知を送信
  - **Time Sensitive Notifications（即時通知）**: APNsの `interruption-level: "time-sensitive"` をサポートし、集中モード時でも重要な通知の割り込み表示とSiriによる自動読み上げ連携を可能とする

## 2. 将来構想・ロードマップ (Phase 2 以降)

以下の機能は、Phase 1 の基盤検証完了後に段階的に設計・実装を検討する構想機能です：

- **通話機能**: 音声通話、ビデオ通話（WebRTC および E2EE シグナリング）
- **ソーシャル拡張**: タグによる投稿検索・ウォッチ
- **位置情報機能**: ユーザー間の安全な位置共有（位置座標の暗号化配送）、スポット情報の紐付け
- **管理者 Web コンソール & 監査 API**: テナント管理者向けのメタデータ監査サーバー API およびダッシュボード画面

---

## 3. 多言語化（ローカライズ）

- アプリ UI は多言語対応とする。まずは日本語をサポートし、将来的に他言語（英語等）を追加できる設計とする。
- UI 文言、システムメッセージ、エラーメッセージはローカライズキーを設計に含めること。設計書中に示す画面ラベルはローカライズキーを併記する。
- すべての文言は `L10n` ラッパーおよび英語ドット記法キー（例: `tab.groups`, `group.role.owner`）で管理する。

## 4. 開発規約

- インデントはスペース2を採用する。
- プロジェクトルートの `.editorconfig` により主要ファイルのインデント設定を管理する。
