# 機能要件とユースケース

## 1. 機能要件

### チャット機能

- 端末間のリアルタイムメッセージ送受信
- E2EE によるメッセージ暗号化
- メッセージ履歴の同期

### アカウント管理

- 匿名アカウントの作成
- 永続アカウントの登録・管理
- Firebase Auth による認証
- 端末移行を実現するための復活の呪文（リカバリフレーズ）発行と管理
- 同じ復活の呪文であれば、異なるデバイスから同一ユーザーとしてログインできる設計

### テナント管理

- テナント（組織）ごとの設定を利用開始前に構成
- テナント管理者による作成・管理
- テナント作成後にテナント情報を含むQRコードを生成・出力（ダウンロード / 印刷）
- 利用者はその QR コードをスキャンしてテナント参加（利用開始）
- サービスのデフォルトテナント設定（指定がなければ自動利用）
- 利用者向けに、QR スキャンの代替としてテナント設定を手動で入力できる `JSON` 入力UI を提供（テンプレート付き）
- 入力はサーバー側でバリデーションし、有効な `tenantId` に解決される
- テナントごとにマスターキーを保持し、個々のユーザー端末のローカル鍵と組み合わせて暗号化・配信
- マスターキーのみでメッセージ内容を復号できない設計
- テナントマスターキーのローテーションポリシーを設計・運用できること
- テナント内のログ・メタデータ取得を可能にするが、本文は閲覧不可

### グループ管理

- テナント内におけるグループの作成・編集・削除・メンバー管理機能
- ユーザーは同一テナント内の複数グループに所属可能
- **デフォルトグループ機能**:
  - テナントごとにデフォルトグループを設定可能（例: 全体通知グループ）
  - 新規ユーザーがテナントに参加した際、デフォルトグループに自動的にアサインされる仕組みを提供

### 通話機能 (Phase2対象)

- 音声通話
- ビデオ通話
- 通信品質の最適化

### ソーシャル機能

- 友達登録・管理（QR コードによる対面追加）
- いいね・リアクション
- タグによる投稿検索・ウォッチ (Phase 2対象)

### 通知

- Firebase Cloud Messaging を利用したプッシュ通知
- **外部システム連携REST APIによる通知送信**:
  - 外部システムからの REST API コールにより、指定した1つのテナント内の指定した複数グループに対して一括で通知を送信
  - **iOSにおける通知仕様**:
    - **Time Sensitive Notifications（即時通知）**: APNsの `interruption-level: "time-sensitive"` をサポートし、集中モード時でも重要な通知の割り込み表示とSiriによる自動読み上げ連携を可能とする

### 位置情報 (Phase2対象)

- ユーザー間の位置共有
- スポット情報の紐付け

## 多言語化（ローカライズ）

- アプリ UI は多言語対応とする。まずは日本語をサポートし、将来的に他言語を追加できる設計とする。
- UI 文言、システムメッセージ、エラーメッセージはローカライズキーを設計に含めること。設計書中に示す画面ラベルは可能であればローカライズキーを併記する。
- エラー管理ではエラーコードとローカライズキーのマッピングを用意し、クライアント側は受け取ったエラーコードに基づいて表示メッセージをローカライズする。

## 開発規約

- インデントはスペース2を採用する。既存ファイルは順次修正する。
- プロジェクトルートの `.editorconfig` により主要ファイルのインデント設定を管理する。
